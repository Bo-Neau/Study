Covariate shiftTraining data and serving data have different input distributions — a subset of data drift. The feature distribution differs between train-time and inference-time. Model Monitor (DataQualityMonitor) detects this. NOT concept drift (X→Y relationship change).

SageMaker Model Monitor — the 4 classes (high-yield Domain 4)
Model Monitor watches a deployed model in production and alerts on drift. Each class watches a different signal. The exam tests whether you can match the symptom in the question to the right monitor. Memory anchor: Data → Quality → Bias → Explainability = inputs, outputs-vs-truth, fairness, feature-importance.

ModelDataQualityMonitor

"The incoming data looks different from training data."
Watches the INPUT features arriving at the endpoint. Compares live data statistics (mean, range, missing values, data types, schema) against a baseline computed from training data. Detects covariate shift — when the distribution of inputs changes even before predictions degrade.
✅ Triggers: "input data drift", "feature distribution changed", "schema mismatch", "missing values increased", "data quality in production" ❌ NOT for prediction accuracy (that's ModelQuality). NOT for fairness (that's ModelBias).

ModelQualityMonitor

"The model's predictions are getting less accurate over time."
Compares model predictions against actual ground-truth labels (which arrive later). Tracks accuracy, precision, recall, F1 for classification; MAE/RMSE for regression. Detects concept drift — when the real-world relationship between X and Y changes. Requires a ground-truth ingestion step because it needs the true answers to compare.
✅ Triggers: "accuracy dropping", "model performance degrading", "predictions vs actual outcomes", "F1 declining in production", "need ground truth labels" ❌ NOT for input drift alone (ModelData). Note: sometimes called "model performance" monitoring — same thing.

ModelBiasMonitor

"The model has started treating demographic groups unequally."
Watches fairness metrics across sensitive groups (age, gender, region) over time. Tracks whether DPL (Difference in Proportions of Labels) and other bias metrics drift past a threshold after deployment. Powered by SageMaker Clarify under the hood. A model fair at launch can become biased as live data shifts.
✅ Triggers: "fairness drift", "demographic groups", "bias appeared after deployment", "DPL increased", "disparate approval rates over time" ❌ NOT for SHAP feature importance (ModelExplainability). NOT for overall accuracy (ModelQuality).

ModelExplainabilityMonitor

"Which feature drives predictions has shifted."
Watches SHAP feature-attribution rankings over time. Alerts when the importance order of features changes — e.g. "age" was the #1 driver of predictions at launch, but "driving history" has overtaken it. Detects drift in why the model decides, not how accurate it is. Also powered by Clarify.
✅ Triggers: "SHAP drift", "feature importance changed", "top feature shifted from X to Y", "attribution ranking changed", "explainability over time" ❌ NOT demographic fairness (that's ModelBias — easy to confuse!). NOT prediction accuracy.
The one distinction the exam loves: Bias vs Explainability
ModelBiasMonitor → WHO is affectedTracks fairness across demographic groups. Answers "is the model unfair to a protected group?" Metric = DPL drift. Keyword = demographic, fairness, group.
ModelExplainabilityMonitor → WHAT drives itTracks which features matter most. Answers "has the reason behind predictions changed?" Metric = SHAP rank shift. Keyword = feature importance, attribution, SHAP.
